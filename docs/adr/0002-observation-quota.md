# ADR-0002 관측 데이터 출처와 할당량 예산

- 상태: 제안
- 날짜: 2026-11-16

| 항목 | 내용 |
|---|---|
| 맥락 | 판정은 두 시점 조회수·라이선스·채널 정보가 필요하다(D2). YouTube Data API v3 기본 일일 할당량 10,000 unit(공식 문서 기준, 콘솔에서 재확인) 안에서 운영해야 한다. |
| 선택 | 관측값은 YouTube Data API v3 `videos.list`(snippet·statistics·status 등, 1 unit/호출, id 50개 묶음)와 `channels.list`(1 unit)만 사용한다. 후보 발굴은 API 대신 워커(vidIQ). `search.list`(100 unit)는 쓰지 않는다. vidIQ 수치는 판정 근거로 쓰지 않는다. |
| 예산(가정) | 단가는 공식 문서 기준(`videos.list`·`channels.list` 1 unit, `search.list` 100 unit), 콘솔에서 재확인. 실행당 후보 상한 200(`01_PRD.md#7` Q3). 수집 직후 1차 관측: `videos.list` 4호출 + `channels.list` 최대 4호출(각 50개 묶음) = 최대 8 unit/회. 기록 검증 1회(대상 200 가정)도 최대 8 unit. 하루 수집 3회 + 검증 10회 가정 → 최대 약 104 unit ≈ 한도의 1%. 역할 구분: `01_PRD.md#5` "예상 사용률 ≤50%"는 목표값, 방어선은 일 사용량 80%(8,000 unit) 초과 시 수집·관측 중지. |
| 대안 | A) vidIQ 수치로 대체: 비공식·스크래핑 의존, 값 일관성 낮음. B) 웹 스크래핑 조회수: 약관·차단 위험. C) `search.list`로 후보 발굴: 100 unit로 예산 급감. 모두 기각. |
| 결과 | 얻는 것: 공식 출처, 예산 여유, 근거 표시 가능. 잃는 것: 후보 수가 크게 늘면 재산정 필요. 가정 수치는 실측(API 사용량 기록) 후 `01_PRD.md#7` Q3 확정. 되돌리는 비용: 낮음(상수 설정). |
| 결정(2026-11-16) | 후보 상한 200·기본 주기 24시간으로 시작(가정, 운영 후 조정). 방어선 도달 안내는 MON-01 오류 상태 문구로 확정. |
