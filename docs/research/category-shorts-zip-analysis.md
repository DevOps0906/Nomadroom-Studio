# 카테고리형 영상제작 배포본 분석 (근거 자료)

> 출처: 사용자 제공 분석(2026-11-18). 기획 정본은 `docs/01_PRD.md`의 카테고리형 제작 장이고, 이 문서는 근거로만 쓴다. 함께 볼 자료는 `Nomadroom_Category_Shorts_PRD.md`(기획서 원문)와 `카테고리형 영상제작_배포용 .zip`이다.

**핵심**: Nomadroom이 먼저 가져올 부분은 `project.json` 편집 명세와 Python·FFmpeg 렌더링 흐름이다. AI가 원본을 보고 제목·훅·자막·화면 구도를 정하면, 렌더러가 그 결정을 검증해 MP4로 만든다. 이 경계를 지키면 기존 소재수집·프리셋·댓글 삽입을 살린 채 카테고리형 쇼츠 완성 영상 출력을 더할 수 있다.

## 1. 압축파일 구성 (약 38.4MB, 29개 파일 — 폰트 3개·예제 영상 2개가 대부분)
| 구성 | 파일·폴더 | 역할 |
|---|---|---|
| 사용 안내 | `쓰는 방법.txt`, `00_먼저읽기.md`, `배포안내.txt` | AI에 ZIP과 원본을 넘기는 방법, 실행 조건, 재배포 안내 |
| AI 제작 지침 | `SKILL.md` | 원본 확인 → 대본 작성 → 렌더링 → 검수 순서 |
| 프리셋 규격 | `references/style.md`, `references/project-format.md` | 제목·자막·화면 규칙, `project.json` 형식 |
| 실행 환경 | `bootstrap.py`, `requirements.txt` | Python 3.11+ 가상환경 생성과 패키지 설치 |

| 음성·렌더링 | `scripts/tts.py`, `scripts/render.py`, `scripts/run.py` | 훅 음성 생성 또는 제공 음성 사용, 합성, MP4 출력 |
| 예제·검증 | `examples/`, `tests/check.py`, `checksums.json`, `검증결과.md` | 한·일 데모, 합성 원본, 입력 검증, 무결성 확인 |

자체 대시보드와 AI 모델 호출 모듈은 없다. AI가 영상·오디오를 확인해 `project.json`을 쓰는 단계는 실행 환경이 맡는다. Python 실행 파일도 포함되어 있지 않다.

## 2. 제작 흐름
흐름도: `docs/diagrams/category-shorts-render-flow.mmd`
1. **원본 준비**: `prepare`가 지정 구간(최대 180초)을 잘라 `source.mp4`를 만든다. 결과로 `analysis.json`과 `sheets/*.jpg`(시간 표시 프레임)가 나온다.
2. **장면 해석**: 전환 후보는 화면 변화량으로 찾는다. 그래서 빠른 움직임도 후보에 들어간다. 0.5초 시트만으로는 짧은 동작이나 대사 뜻을 놓칠 수 있으므로 최종 컷과 자막은 원본을 확인한 뒤 정한다.
3. **편집 명세**: 언어, 제목 2줄, 훅, 컷별 배율·세로 위치, 자막 문구·시간을 담는다. 타임코드는 `source.mp4`의 0초 기준이다(원본 전체 시각이 아님).
4. **렌더링**: Pillow로 글자를 그리고 FFmpeg로 합성한다. 훅 음성이 첫 자막 구간에 들어가지 않으면 멈추고 필요한 길이를 안내한다.
5. **검수**: 산출물은 MP4, `.hook.wav`, `.report.json`(해상도·길이·오디오 유무·훅 시점)이다. 피사체 잘림, 가독성, 음량은 재생으로 확인한다.

## 3. 편집 규격
| 항목 | 기본값 |
|---|---|
| 출력 | 608×1080, 30fps, H.264/AAC. 1080×1920은 별도 프리셋 |
| 상단 제목 | 280px 검정 영역에 두 줄. 한국어 흰·노랑, 일본어 흰·흰 |
| 구도 | 중앙 크롭 후 구간별 배율·세로 위치. 핵심 피사체(얼굴·손·악기 등) 보존 |
| 자막 | 흰색 내레이션, 노란색 괄호(속마음), 초록 강조(반응). 동시 표시 금지 |
| 음성 | 첫 훅만 TTS. 훅 구간 원본 20% → 복원 → 전체 정규화 |
| 언어 | 한국어 기본. 일본어는 별도 텍스트·별도 MP4(InJoon / Nanami) |

`shots`의 "컷"은 재배열이 아니다. 시간순으로 재생하면서 배율과 위치만 바꾸므로 원테이크형 카테고리 프리셋에 맞는다. 예능형 재배치나 롱폼→여러 쇼츠는 원본 구간과 출력 순서를 표현하는 별도 명세가 필요하다.

## 4. Nomadroom 적용
| 영역 | 가져올 부분 | 정할 사항 |
|---|---|---|
| 소재수집 | 선택 원본에서 분석 영상·시간 시트 생성 | 기존 "제작 가능 → 영상 만들기" 흐름을 쓴다. URL이 어려우면 파일 첨부로 넘어간다 |
| 카테고리형 프리셋 | 두 줄 제목, 자막 3종, 구간별 구도, 첫 훅 음성 | 원테이크형 안의 스타일로 추가하고, 공통 기능은 바꾸지 않는다 |
| 댓글 삽입 | 배포본 기본 스타일에는 댓글 카드가 없다 | 기존 댓글 자동 삽입 설정을 유지하고 렌더러에 댓글 카드 레이어를 연결한다. 자막과 겹침을 검수 |
| 출처·라이선스 | `analysis.json`에 원본 URL·업로더 일부 기록 | 원본 URL·저작자·라이선스·편집 권한 기록을 작업에 연결하고, 일반 자막과 권리자 표시를 구분 |
| 한·일 | 언어별 제목·자막·훅 | 같은 원본 구간·구도를 재사용하고 텍스트·음성만 바꿔 별도 렌더 |
| 결과 확인 | MP4, 훅 음성, 리포트 | 원본 준비 → 편집안 검토 → 렌더링 → 검수 상태와 다운로드 |

### 먼저 보강할 세 가지
1. **입력 경로를 서버 기준으로**: 현재 코드는 JSON에서 절대 파일 경로도 받는다. 통합할 때는 작업 ID와 저장 파일 ID만 넘기고, 경로는 작업 폴더 안에서만 결정한다. URL 작업은 실행 권한과 네트워크 범위를 제한한다.
2. **문서에만 있는 규칙을 검수 화면에**: "자막 1.4초 이상"은 지침에만 있고 `validate()`는 검사하지 않는다. 겹침과 공백은 차단하고, 짧은 읽기 시간과 피사체 잘림은 타임라인 경고로 보여 준다.
3. **렌더링을 요청과 분리**: 프레임마다 Python에서 확대·선명화·합성을 한다. 개인용은 로컬 워커로 충분하고, 여러 작업은 큐와 별도 워커를 둔다. TTS가 실패하면 재시도하거나 `hook_audio` 대체 음성을 쓴다.

## 5. 확인 범위와 개발 순서
- 확인한 것
  - SHA-256 27개가 모두 일치했다.
  - 동봉 MP4 2개는 모두 8초, 608×1080, 30fps, H.264/AAC였다.
  - Linux에서 언어별 검증 테스트 6개씩 통과했다.
  - 합성 원본으로 구간 추출, 시트 생성, 제공 음성 재렌더링을 재현했다.
- 이번에 재시험하지 않은 것: 온라인 Edge TTS와 외부 URL 다운로드. 이 둘은 배포본 자체 검증(Windows)에만 기록되어 있다.
- 권장 순서: 한국어 한 편 → 댓글·출처 레이어 → 일본어 → 예능형·롱투숏. 1단계 완료 기준은 소재수집(정체) 후보 한 건으로 두 줄 제목·컷별 자막·훅 음성이 들어간 MP4와 리포트를 받는 것이다.
