# ADR-0001 수집 워커 실행 위치

- 상태: 제안
- 날짜: 2026-11-16

| 항목 | 내용 |
|---|---|
| 맥락 | 후보 수집은 운영자 PC의 Chrome·vidIQ 로그인 프로필이 필요하다(Q1). 웹·DB는 클라우드가 자연스럽다. 워커 위치와 비밀 분리를 정해야 한다. |
| 선택 | 하이브리드: 웹(Next.js)·Supabase·API(FastAPI)는 클라우드, **수집 워커만 운영자 PC**. 워커는 아웃바운드 HTTPS로 FastAPI `/worker/v1/*`만 폴링·결과 전송하고 DB에 직접 접속하지 않는다. 워커 토큰은 워크스페이스 범위(`01_PRD.md#8`). YouTube 키·service_role은 클라우드 API에만 둔다. |
| 대안 | A) 전부 운영자 PC: 포트 개방·외부 접속·가동 의존이 커서 웹 접근성이 낮음. B) 전부 클라우드 헤드리스 Chrome: vidIQ 로그인 유지·봇 차단·약관 위험, 프로필 복제 필요. C) 워커가 Supabase 직접 접속: service_role 또는 넓은 DB 권한이 PC에 퍼짐 → 기각. |
| 결과 | 얻는 것: 로그인 프로필이 PC 밖으로 나가지 않음, 워커에 비밀 최소(워커 토큰), 인바운드 포트 없음. 잃는 것: 운영자 PC가 꺼져 있으면 수집 불가, 작업 폴링·하트비트·재시도 설계 필요. 되돌리는 비용: 낮음(워커 코드는 `apps/api/worker` 한 곳, 호스트만 바꾸면 B로 이전 가능). |
| 결정(2026-11-16) | API는 클라우드, 호스팅처는 08 배포 단계에서 선택. 워커 토큰은 운영 절차로 발급·폐기, 회전 90일(가정). PC 오프라인 안내 문구는 MON-01 구현 때 확정. |
